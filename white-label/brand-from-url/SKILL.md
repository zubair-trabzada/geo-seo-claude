# Brand-From-URL

One-shot bootstrap skill that replaces the manual `brand.json` edit step. Give it a website URL, it scrapes the public homepage, and writes the `brand.json` that `white-label/brand_config.py` loads, so any report generator built on `load_brand()` picks the brand up with no further changes.

## When this fires

- *"Pull my brand info from example-agency.com"*
- *"Set up my brand from my website"*
- *"Auto-detect my brand"*
- A downstream skill needs `brand.json` and the file doesn't exist
- Anyone asking "can it scrape brand from a website instead of brand.json?"

## What it extracts

| Field | Source (in priority order) |
|---|---|
| `company_name` | `og:site_name` → `<title>` (split on separators) → hostname |
| `tagline` | `og:title` extra after separator |
| `description` | `og:description` → `<meta name="description">` |
| `logo_url` | `og:image` → `apple-touch-icon` → `<img>` with "logo" in src/alt/class → `<link rel="icon">` |
| `favicon_url` | `<link rel="icon">` / `shortcut icon` |
| `primary_color` | Darkest of the detected colors: meta `theme-color`, CSS `--brand`/`--primary`/`--accent` vars, and the dominant non-neutral colors in the logo. A logo color that only approximates a declared one is dropped in favor of the declared value |
| `accent_color` | Same sources, chosen to maximize luminance contrast vs. primary |
| `contact_email` | regex over page text, prefers `@<sitedomain>` matches |
| `contact_phone` | regex over page text |
| `address` | schema.org `PostalAddress` JSON-LD (when present) |
| `social_links` | `<a href>` matching linkedin/x/twitter/facebook/instagram/youtube/tiktok |

## Flow (every invocation)

1. **Get the URL.** If the user didn't give one, ask: *"What's your company website?"*

2. **Run the extractor.** The path is relative to this skill's folder, `white-label/brand-from-url/`. It writes a preview file and prints a summary of what it found:
   ```bash
   python3 scripts/brand_extractor.py <URL> /tmp/brand_preview.json
   ```

3. **Show the user what was detected** as a clean readable table:
   ```
   Detected from https://example-agency.com:
     Company:     Example Agency
     Tagline:     Practical growth tools for local businesses
     Logo:        https://example-agency.com/assets/logo.svg
     Primary:     #0A1E3F  (deep navy)
     Accent:      #D4AF37  (gold)
     Email:       hello@example-agency.com
     Phone:       (555) 010-1234
     LinkedIn:    https://linkedin.com/company/example-agency
     Twitter/X:   https://x.com/exampleagency

   Look right? I'll write this to brand.json on confirm.
   (Reply with corrections — e.g. "primary is #1A2B5C", "phone is wrong", etc.)
   ```

4. **Wait for confirm or corrections.** Apply any edits.

5. **Save it** as `brand.json` in the directory the report generator runs from (or the path the user or calling skill specified): take the preview file, apply any corrections, and write the result there. Mention that the file is ready and that `brand_config.load_brand("brand.json")` will pick it up.

## Calling from another skill

If a report-generating skill finds that `brand.json` is missing, it should NOT prompt the user for individual fields. Instead it should call this skill:

```
"Before I build the report, what's your company website?
 I'll pull your brand colors and contact info so the PDF is white-labeled.
 (Or reply 'skip' for the default branding.)"
```

Then on URL → invoke `scripts/brand_extractor.py` → show preview → confirm → write cache → continue with the original task.

## Output schema (`brand.json`)

By default the extractor writes the white-label schema that `brand_config.load_brand()` deep-merges over its defaults. Everything else it detected is kept under `_extracted`, which `load_brand()` ignores because the key starts with an underscore:

```json
{
  "_comment": "Auto-generated by brand-from-url from https://example-agency.com. Edit any field by hand; brand_config.load_brand() deep-merges this over the defaults. Detected detail is preserved under _extracted (ignored by load_brand because the key starts with _).",
  "name": "Example Agency",
  "cover_tag": "Generative Engine Optimization Audit",
  "website": "example-agency.com",
  "phone": "(555) 010-1234",
  "contact_name": "",
  "colors": {
    "primary": "#0A1E3F",
    "primary_bright": "#364661",
    "secondary": "#D4AF37",
    "text_accent": "#0A1E3F"
  },
  "_extracted": {
    "source_url": "https://example-agency.com",
    "tagline": "Practical growth tools for local businesses",
    "description": "...",
    "logo_url": "https://example-agency.com/assets/logo.svg",
    "favicon_url": "https://example-agency.com/favicon.ico",
    "all_extracted_colors": [
      "#0A1E3F",
      "#D4AF37"
    ],
    "contact_email": "hello@example-agency.com",
    "address": "123 Main Street, Exampletown, CA, 90210",
    "social_links": {
      "linkedin": "https://linkedin.com/company/example-agency",
      "twitter": "https://x.com/exampleagency",
      "facebook": null,
      "instagram": null,
      "youtube": null,
      "tiktok": null
    },
    "warnings": []
  }
}
```

Pass `--raw` to get the flat extraction dict instead (`company_name`, `tagline`, `description`, `logo_url`, `favicon_url`, `primary_color`, `accent_color`, `all_extracted_colors`, `contact_email`, `contact_phone`, `address`, `social_links`, `warnings`).

## Caveats to share with the user upfront

- **JS-heavy sites are flakier.** Squarespace/Webflow/Wix usually expose everything in static HTML. A heavy React/Next site behind client-side rendering may need the user to paste fields manually for anything the homepage doesn't ship in the initial HTML.
- **Auto-detected colors are right ~80% of the time.** Always confirm before locking the cache, otherwise downstream PDFs come out off-brand.
- **The cache is local.** No data leaves the user's machine; the only outbound call is the one HTTP GET to their own homepage (and one GET per logo image).
